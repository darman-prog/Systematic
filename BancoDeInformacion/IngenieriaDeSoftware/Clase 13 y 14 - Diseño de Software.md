# Evaluación del diseño
El equipo evalúa el modelo para verificar:
- Errores
- Inconsistencias
- Omisiones
- Cumplimiento de restricciones de costo y tiempo
- Viabilidad técnica.

# Deuda técnica
Ocurre cuando se elige una solución rápida en lugar de una mejor solución de diseño.

Consecuencias:
Mayor esfuerzo de mantenimiento
Código difícil de modificar
Incremento del costo del proyecto.

# Diversificación y convergencia
Diversificación: generar múltiples alternativas de diseño.

Convergencia: evaluar alternativas y seleccionar la mejor solución según requerimientos funcionales y no funcionales.

# Diseño de datos / clases
Recordemos… Una clase es una plantilla o molde que define cómo serán los objetos de un programa: qué datos tendrán y qué acciones podrán realizar.

# Ideas finales
El diseño es el cimiento del software.

Sin buen diseño:
El sistema puede ser inestable
Difícil de probar
Difícil de mantener

Un buen diseño permite software de calidad, mantenible y escalable.
